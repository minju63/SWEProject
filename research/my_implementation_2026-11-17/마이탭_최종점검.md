# 마이 탭 최종 점검 — 2026-11-17

## 이번 작업 범위

SRS_v0.8_수정.docx의 마이 기능을 기준으로 프로필·관심분야, 찜, 최근 본 혜택, 신청 관리와 계정 화면을 보완했다. 앞서 제외하기로 한 아이디·이메일·비밀번호 변경, 알림, 약관 동의 기능은 이번 완료 범위에 포함하지 않는다. 홈 AI 추천이나 지도 구현은 수정하지 않았다.

## 수정한 오류

- 프로필을 불러오는 도중 기존 값이 입력 중인 값을 덮어쓰던 문제: 로딩 중 편집을 막고, 편집한 초안은 배경 조회 결과로 초기화하지 않도록 수정했다. 입력 항목 변경도 이전 초안을 기준으로 합친다.
- 준비물을 연속 체크할 때 앞선 결과가 덮어써질 수 있던 문제: 저장 대기열이 마지막 조회 결과를 기준으로 처리하도록 수정했다.
- 저장 실패에도 신청 준비 화면이나 준비물 입력창이 닫히던 문제: 저장 성공을 확인한 뒤에만 닫도록 수정했다.
- 예전 대분류만 저장한 관심분야가 설정에서 선택되지 않은 것처럼 보이던 문제: 기존 대분류 선택은 전체 세부분류 선택으로 읽는다. 서로 다른 대분류의 ‘기타’는 독립적으로 저장한다.
- 준비 조건을 항상 하나의 일반 안내로 표시하던 문제: 실제 정책과 현재 맞춤정보를 비교해 표시한다. 확인되지 않은 조건은 확인 필요로 유지하고, 확인된 불충족은 대상 아님으로 구분한다.
- 마이의 ‘신청 가능’ 필터가 모집 상태만 보던 문제: 모집 중·상시이며 실제 조건 판정이 신청 가능한 찜만 표시한다.

## 저장 위치와 검증의 한계

- 정책 원본은 기존 공용 `policy` 및 연결 테이블을 사용한다. 검증 과정에서 공용 정책 값을 변경하지 않았음을 해시 비교로 확인했다.
- 프로필·찜·최근 조회·등록 정책 신청·준비물·후속 행동은 기존 사용자 테이블을 사용한다. 이름과 추가 선택정보 일부는 해당 계정의 Supabase Auth 사용자 정보에 저장된다.
- 직접 입력한 혜택과 추가 날짜는 기존 `user-workspaces` 비공개 Storage의 사용자별 기록에 저장한다. 공용 정책으로 새로 등록하지 않는다.
- 익명 사용자와 브라우저에서 비공개 Storage를 직접 읽거나 쓰는 요청이 거부되는 것을 실제로 확인했다. 사용자 간 소유권은 분리된 백엔드 검사로도 확인했다.
- 행정기관의 실제 접수·심사·선정 결과를 자동 조회하는 기능은 아니다. 신청 상태와 결과는 사용자가 직접 기록한다.
- 정책 자체의 자격 조건이 검증되지 않았으면 ‘신청 가능’으로 단정하지 않는다. 이 작업은 정책 원문의 누락된 조건을 새로 수집하는 작업을 포함하지 않는다.
- 실제 정책 목록을 처음 불러올 때 5초를 넘긴 응답이 있었다. 이번 검증은 기능·저장값 일치 검증이며, SRS의 일반 조회 95% 2초 이내 성능 기준을 별도로 측정한 결과는 아니다.
