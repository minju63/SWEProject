# 마이 기능 보완 및 화면 연결 (2026-11-17)

이번 범위는 아이디·비밀번호 등 계정 변경, 알림, 약관·동의를 제외한 마이 기능과 홈·캘린더 연동입니다. AI 비서, 다른 분야 전체 정책의 DB 통합, 지도의 실제 장소 데이터 수집은 이 작업의 완료 범위에 포함하지 않습니다.

## 저장 방식과 제한

현재 공유 DB의 user_application.policy_id는 필수값이라 직접 입력한 혜택을 넣을 수 없습니다. 공통 정책을 오염시키거나 공유 스키마를 임의로 바꾸지 않기 위해 직접 입력 내역과 추가 날짜는 Supabase Storage의 비공개 `user-workspaces` 버킷에 보관합니다. 객체 이름은 인증된 사용자 UUID이며 서버에서만 읽고 씁니다. 기존 등록 정책과 사용자 테이블의 값은 기존 방식으로 저장합니다.

개인 파일의 변경은 현재 단일 API 프로세스에서 사용자별로 순서를 보장합니다. 여러 API 서버로 확장할 때는 별도 관계형 테이블과 DB 트랜잭션으로 옮기는 작업이 필요합니다. 직접 입력 내역은 계정당 100개, 개인 파일은 256KiB까지입니다. 개인 파일이나 준비 체크를 Auth 사용자 메타데이터·JWT에 담지 않습니다.

## 테스트 계정

실제 앱 프로젝트에 테스트 전용 계정 1개를 만들고 로그인까지 확인했습니다. 이메일과 비밀번호는 프로젝트 루트 `.local/test-account.json`에서 확인합니다. 이 폴더는 Git 제외 대상이며 서비스 키를 브라우저에 전달하지 않습니다. 테스트 계정에는 검증 중 만든 개인 신청내역·찜·최근 조회가 남아 있습니다. 기존 사용자의 기록은 수정하지 않았습니다.

브라우저에서 `http://localhost:5173/my`를 열고 로그인합니다. 테스트 전용 메일 주소이며 메일 인증 없이 바로 로그인할 수 있습니다. 개발 환경의 프런트 API 주소는 `/api/v1`로 맞춰 localhost와 127.0.0.1 혼용에 따른 CORS 오류를 제거했습니다.
