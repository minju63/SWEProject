# 주거·생활 자격 조건 JSON 반영 결과 — 2026-11-18

기준 문서는 [새로 지정한 공유문서](https://docs.google.com/document/d/1bGTF7Hhz3NrL4pyLFNWZtjjLoaxBVL4A)의 ‘신청 자격 조건 저장 및 검증 기준’과 ‘정책 신청 자격 조건 추가 조사 및 검증’입니다. 공유문서 자체를 편집한 작업은 아닙니다.

## 실제 DB에 반영한 내용

- 주거·생활 정책 79건의 `policy.eligibility_conditions`를 `required`, 중첩 `AND`·`OR`, `exclusions`, `RAW` 형식으로 정리했습니다. 기존 조건의 대상자·단위·기준일과 AND/OR 관계는 보존했습니다.
- 공식 출처 URL, 실제 재접근 시각, 원문 발췌, 본문 해시, 기존 출처 식별자를 JSON에 기록했습니다. 원문 발췌는 전체 공고가 아니라고 표시했습니다. 현재 재접근 자료는 앞선 작업의 `housing_conditions_2026-11-18/sources/`에 보관되어 있고, `policy_source.raw_data`에는 이전 수집 원문도 그대로 남아 있습니다.
- 확인된 일부 조건 11개는 근거 문구와 함께 필수 조건에도 기록했습니다. 나머지는 기존 검토 조건을 보존하면서 `RAW`로 표시했습니다. 기존 검토 내용을 공식 원문 전체의 검증 완료로 승격하지 않았습니다.
- `RAW`에는 자동 판정 불가 이유와 원래 검토 조건을 남겼습니다. 프로필·판정기 추가가 필요한 대상자·필드·기준일은 별도 목록으로 분리했습니다.
- 사용자 예시의 거주지 OR 구조를 드림옷장의 전체 자격으로 저장하거나, 주거 정책에 복사하지 않았습니다.

## 아직 완료되지 않은 일

**전체 공식 공고와 모든 필수·제외·예외 조건을 대조하는 검증은 아직 끝나지 않았습니다.** 이번 작업은 기존 주거 조건 자료의 공통 형식 반영과 판정 코드 연결입니다. 누락 조건이 전혀 없다는 의미가 아닙니다.

따라서 별도 DB 컬럼 `policy.eligibility_verified`는 79건 모두 **false**입니다. JSON 안의 표시만 바꿔 검증 완료로 처리하지 않았습니다. 앞으로 정책별 전체 공고 대조가 완료된 건에 한해서만 이 컬럼을 true로 변경해야 합니다.

## 판정 코드

- 화면과 API가 같은 조건 판정 모듈을 사용하도록 연결했습니다. `required`·`exclusions`를 우선 읽고 기존 `all`·`exclude` 형식도 지원합니다.
- AND는 모두 충족, OR는 하나 이상 충족으로 계산합니다. 모르는 조건을 거짓으로 가정하지 않습니다.
- 제외 조건에 해당하면 신청 불가, 제외 여부가 불명확하면 확인 필요입니다.
- `RAW`는 필드나 비교 값이 같이 들어 있어도 자동 충족 처리하지 않습니다. 지원하지 않는 가족 대상자·기준일·필드도 확인 필요입니다.
- 전체 검증 전에는 일부 조건이 맞거나 달라도 전체 자격을 확정하지 않습니다. 현재 주거 정책의 전체 판정은 확인 필요입니다.
- 잘못된 형식, 비어 있는 조건, 잘못된 값 형식으로 신청 가능 판정이 나지 않도록 했습니다.

## 검증 결과

- 실제 DB 79건을 반영안과 대조했습니다. 조건 JSON과 자동 갱신 시각 외의 정책 값 및 다른 분야 정책은 변경하지 않았습니다.
- 재시작한 실제 API의 공개 카탈로그에서 79건의 JSON과 false 검증 표시를 다시 확인했습니다.
- 전용 테스트 계정으로 실제 자격 비교 API 6건을 호출했습니다. 새 중첩 조건을 읽고 RAW가 UNKNOWN으로 유지되는 것을 확인했습니다. 테스트 중 정책·프로필 값을 수정하지 않았습니다.
- 화면·조건 테스트 14개, 백엔드 테스트 10개, TypeScript 검사와 빌드 통과.

추가 입력·판정 코드가 필요한 항목은 [별도 정리](프로필_판정기_추가필요.md)를 참고하면 됩니다. 상세 반영 기록은 `result.json`, 실제 API 검증은 `live_verification.json`에 있습니다.
