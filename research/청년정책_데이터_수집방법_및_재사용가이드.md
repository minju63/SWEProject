# 청년 주거·생활비 정책 데이터 수집 방법 및 재사용 가이드

작성일: 2026-11-11  
수집 사례 기준일: 2026-10-02, 이후 후속 대조 기록 포함

## 1. 문서 목적

이 문서는 청년 주거·생활비 정책 데이터를 어떤 자료에서 수집하고, 어떤 기준으로 정리·검증했는지 설명한다. 다른 프로젝트에서 같은 방식을 적용할 수 있도록 수집 절차, 데이터 구조, 판정 규칙과 주의점을 함께 정리했다.

실제 작업은 **공공 API로 후보를 수집하고, 공식 홈페이지와 공고문을 추가 조사한 뒤, 사람이 자격조건과 예외를 대조하여 표준 파일로 내보내는 방식**으로 진행했다. 전체 과정을 자동 처리하는 크롤러나 자동추천 시스템을 구현한 것은 아니다. 현재 결과물은 JSON·TSV·엑셀 등 파일 기반 데이터이며, DB 서버에 적재하는 과정은 이 수집 작업의 범위에 포함되지 않는다.

## 2. 조사 범위와 결과

조사 분야는 청년주택, 월세·전세 지원, 이사비 지원, 공과금·교통비 지원이다. 지역은 전국·부산·부산진구·사하구를 중심으로 정리했으며, 타지역 사업도 전입예정자 등 신청 경로가 있는지 검토했다.

## 3. 전체 작업 흐름

```text
조사 분야·지역·기준일 설정
  → 공공 API에서 후보 목록 수집
  → 공식 기관 홈페이지와 모집공고 추가 조사
  → API·HTML·PDF·HWPX 원문 보관 및 텍스트 추출
  → 사업·기관·연도·회차 일치 여부 대조
  → 자격조건·지원내용·기간을 표준 컬럼으로 정리
  → 예외 경로와 미확인 항목 별도 기록
  → 구조·원문 연결·증빙 검증
  → JSON·TSV·CSV·엑셀 등으로 내보내기
```

API는 후보를 찾는 데 사용하고, 실제 지원조건과 모집상태는 공식 안내·공고·첨부자료와 비교했다. 기존에 정리한 데이터도 최신 정보로 간주하지 않고 재검토할 후보로 활용했다.

## 4. 원천자료 수집 방법

### 4.1. 온통청년 Open API

사용한 엔드포인트는 `https://www.youthcenter.go.kr/go/ythip/getPlcy`이다. 아래는 당시 실제 요청 조건이며, 다른 프로젝트에서 사용할 때는 제공기관의 최신 명세와 승인 범위를 별도로 확인해야 한다.

| 목적 | 요청 조건 |
| --- | --- |
| 주거 분야 후보 수집 | `lclsfNm=주거`, `pageNum=1~4`, `pageSize=100`, `rtnType=json` |
| 교통 관련 후보 탐색 | `plcyNm=교통`, `pageNum=1`, `pageSize=100`, `rtnType=json` |
| 지역 필터 작동 비교 | `zipCd=26230`과 `zipCd=26380`을 각각 요청 |

주거 후보 수집 시 연령·소득·모집 여부 필터는 적용하지 않았다. 처음부터 좁게 필터링하면 예외 자격이나 지역 이동 경로가 있는 정책을 놓칠 수 있기 때문이다.

API 키는 프로젝트의 `.env`에서 `YOUTHCENTER_API_KEY`로 읽었다. 수집 스크립트는 API 요청 URL 전체 대신 기본 엔드포인트와 요청 조건을 로그에 기록하고, 저장 텍스트에서 키 문자열을 치환하도록 작성했다. 다른 프로젝트로 전달할 때도 `.env`나 실제 인증키는 포함하지 않는다.

지역 요청 비교에서는 두 응답의 첫 페이지 정책 ID 100개가 동일했다. 따라서 지역 필터가 정상 작동한다고 판단하지 않았고, 실제 지원대상 원문으로 지역 조건을 다시 확인했다. `pageSize=100`은 요청값이며 API 승인 호출한도나 제공기관 갱신주기를 확인한 값은 아니다.

### 4.2. 공식 홈페이지와 공고문 추가 조사

API에 없는 사업, 오래된 정보, 불명확한 조건을 보완하기 위해 다음 공식 기관을 조사했다.

| 범위 | 주요 자료 제공처 | 확인 내용 |
| --- | --- | --- |
| 전국 주거 | 국토교통부, 마이홈포털, LH청약플러스 | 월세 지원, 공공임대, 청년주택, 실제 모집공고 |
| 대출·보증 | 주택도시기금, 한국주택금융공사 | 대출·보증 대상, 소득·자산, 상품별 예외 |
| 생활비·기숙사 | 한국장학재단, 에너지바우처 등 | 주거장학금, 생활관, 에너지 지원 |
| 부산 | 부산시, 부산청년플랫폼, 부산도시공사 | 지역 주거·이사비·교통 지원과 정정공고 |
| 부산진구·사하구 | 구청과 공식 청년정책 사이트 | 구 주민 대상 사업, 프로그램, 청년주택 |

검색에는 `2026 청년월세`, `전세임대`, `버팀목`, `머물자리론 변경공고`, `이사비 중개보수`, `부산진구 주거`, `사하구 청년주택` 등을 사용했다. 후보별 재검토에서는 기관명·사업명 검색과 사업명 핵심문구·연도 검색을 병행했다.

검색 결과는 공식 자료를 찾는 통로로 사용했다. 블로그·SNS·재가공 정보만으로 자격조건을 확정하지 않았으며, 기관·사업·연도가 다른 동명 공고는 해당 정책의 근거로 채택하지 않았다.

### 4.3. 원문 다운로드와 텍스트 추출

Node.js 수집 스크립트로 API 응답과 공식 웹페이지를 다운로드했다. 초기 수집 스크립트는 요청을 최대 4개씩 묶어 실행하고, 개별 요청에 20초 제한을 적용했다. 이는 해당 스크립트의 설정이지 제공기관이 보장한 호출 기준은 아니다.

자료는 `raw_2026-10-02/` 아래에 보관했다.

- API 응답: JSON 원문 저장
- 웹페이지: HTML 원문과 태그를 정리한 TXT 저장
- PDF·HWPX 첨부: 파일 확보 후 텍스트를 추출하여 조건 대조에 활용
- 수집 로그: URL, 요청 조건, 확인일, HTTP 상태, 콘텐츠 유형, 파일 크기, 파일 경로, SHA-256 해시 또는 오류 기록

HTML 텍스트 변환에서는 스크립트·스타일·주석·태그를 제거하고, HTML 엔티티와 줄바꿈·공백을 정리했다. 텍스트 추출본은 검토를 돕는 자료이며, 표 구조나 문맥이 불명확하면 원본을 함께 확인해야 한다.

파일 다운로드 성공이나 HTTP 200 응답만으로 해당 정책의 모집상태·자격·최신성을 확정하지 않았다. 해시 역시 파일 식별과 비교를 위한 기록이며 내용의 정확성을 보장하지 않는다.

## 5. 후보 선별과 정책 단위 정리

후보는 정책명만 비교하지 않고 시행기관, 지원내용, 대상, 연도, 모집 회차, 신청기간을 함께 확인했다.

1. 개인이 신청할 수 있는 정책·프로그램·시설인지 확인한다. 건립계획이나 공급계획을 현재 입주 모집으로 취급하지 않는다.
2. 공식 지원대상으로 신청범위를 판단한다. 기관 주소나 주택 소재지만 보고 구 주민 전용 사업으로 분류하지 않는다.
3. 현재 거주지 외에 전입예정·입주 후 전입·학교·직장 활동 인정 경로가 있는지 확인한다.
4. 동일 사업의 중복 등록은 표준행과 연결하고, 자격·혜택이 다른 유형은 필요하면 별도 행으로 분리한다.
5. 확인한 사실, 보류 사유, 불채택 근거와 남은 확인사항을 후보 판정 기록에 남긴다.

정책을 찾지 못했거나 최신 공고를 확보하지 못한 경우는 사업이 없거나 신청할 수 없다는 결론과 구분했다.

### 6.2. 값 정리 규칙

- 날짜는 확인 가능한 경우 `YYYY-MM-DD`로 정리한다. 월 단위 정보만 있을 때 임의로 월말 날짜를 만들지 않는다.
- 신청기간과 운영기간·지급기간·결과발표일을 구분한다.
- 진행상태는 모집예정·모집중·상시·마감·확인필요로 구분한다. 기간이 없다는 이유만으로 상시모집으로 바꾸지 않는다.
- 조건이 없다고 확인된 값은 `제한없음`, 근거가 부족한 값은 `확인필요`로 구분한다.
- 여러 값은 필요한 경우 세미콜론으로 구분하되, 조건의 AND·OR 관계는 원문과 자격경로에 별도로 보존한다.
- 지원대상 원문은 읽은 자격 구간의 문구를 보존하고, 태그·레이아웃 공백을 정리한다. 전체 페이지나 전체 첨부를 모두 해석했다는 의미는 아니다.
- 금액은 상한·횟수·지급기간·차감 규칙을 함께 기록한다. 월 최대 금액을 모든 신청자의 확정 수령액으로 해석하지 않는다.

기존 파일에는 숫자와 `확인필요` 같은 문자열이 함께 쓰인다. 다른 프로젝트에서 SQL DB로 옮긴다면 숫자·날짜 컬럼에는 실제 값 또는 NULL을 저장하고, 확인상태와 원문을 별도 컬럼으로 분리하는 방식을 권장한다. 이는 재사용을 위한 제안이며 현재 파일에 적용된 DB 스키마는 아니다.

### 6.3. 예외 자격 보존

최소·최대연령만으로 전체 신청 가능 여부를 판단하지 않았다. 기본 경로와 대학생·취업준비생·병역·혼인 등 예외 경로를 `housing_rules_2026-10-02.json`에 별도로 정리했다.

예를 들어 청년월세 지원은 공통조건과 원가구 심사 조건을 나누고, 원가구 심사 면제 사유를 OR 경로로 보존했다. 이는 수집 당시 조건을 어떻게 구조화했는지 보여주는 사례이며 현재 신청자격 안내로 사용하려면 최신 공고를 확인해야 한다.

명확히 확인된 불일치만 제외 근거로 사용하고, 미입력·모름·확인필요는 확정 부적격으로 취급하지 않는 방향으로 설계했다. 자동추천 엔진은 구현하지 않았다.

| Candidates | API 후보별 판정, 공고 대조, 확인기간, 최신성 한계, 증빙 | API 정책 ID와 연결data_id |

318개 주거 후보 모두에 대해 공식 연결 URL 조회와 사업명 검색 기록을 남겼지만, 이를 318개 최신 모집공고 검증 완료로 표현하지 않았다. 재조회일과 본문 대조일을 별도로 기록하고, 재조회했다는 이유만으로 표준행의 모집상태나 최종확인일을 자동 갱신하지 않았다.

## 8. 검증과 결과 파일 생성

확인한 검증 항목은 다음과 같다.

- 표준 데이터가 58행·44컬럼인지 확인
- 정책행과 별도 원문 기록의 지원대상 내용이 일치하는지 확인
- 연결한 원문 파일이 실제 존재하는지 확인
- 후보 판정의 증빙 경로와 추가조사표의 공유 항목 일치 여부 확인
- 검증 스크립트가 검사하는 내보내기 파일에 실제 API 키가 포함되지 않았는지 확인

자동 구조 검증은 파일의 형식과 연결을 확인하는 작업이다. 모든 조건 해석, 후속 정정공고, 잔여 예산·공실까지 검증하는 것은 아니다.

내보내기는 JSON·CSV·TSV·XLSX·Markdown 형식으로 구성했다. CSV·TSV는 UTF-8 BOM과 따옴표 처리를 사용하고 셀 내부 원문 줄바꿈을 보존하도록 작성했다. 엑셀에서는 XLSX를 사용하거나 텍스트 가져오기 기능으로 구분자와 인코딩을 지정하는 것이 적절하다. 실제 전달 시에는 필요한 형식의 파일이 생성되어 있는지 확인한다.

주요 구현 파일은 다음과 같다.

| 파일 | 역할 |
| --- | --- |
| `collect_housing_2026-10-02.cjs` | 초기 API·웹 원문 수집과 로그 저장 |
| `prepare_housing_2026-10-02.cjs` | 조사·대조한 내용을 표준 데이터로 구성하고 내보내기 |
| `housing_export_utils.cjs` | HTML 텍스트 정리, CSV·XLSX·Markdown 생성 보조 |
| `validate_housing_2026-10-02.cjs` | 행·컬럼 수, 원문 연결, 일부 내보내기 파일의 키 포함 여부 검사 |
| `verify_housing_candidates_2026-10-02.cjs` 등 후속 스크립트 | 후보별 공식 자료 조회·공고 대조와 후속 조사 |

기존 수집 스크립트는 과거 Git 커밋의 데이터, 로컬 원문, 날짜별 파일과 수동 대조 결과에 의존한다. 검증 스크립트에도 준비 스크립트 문구를 수정하는 동작이 포함돼 있다. 다른 프로젝트에서 파일 몇 개를 복사해 실행하면 전체 결과가 그대로 재현되는 구성은 아니므로, 경로·입력자료·변경 동작을 먼저 점검해야 한다.

## 9. 다른 프로젝트에 적용하는 방법

다음 절차는 기존 작업에서 얻은 재사용 지침이며, 자동화가 이미 구현돼 있다는 뜻은 아니다.

1. **범위를 정한다.** 분야, 대상 지역, 조사 기준일, 포함할 데이터유형을 먼저 정한다.
2. **공통 스키마를 정한다.** 정책 식별자, 대상조건, 혜택, 기간, 상태, 출처, 확인일을 정의한다.
3. **API 후보를 원문 그대로 보관한다.** 요청 조건과 페이지별 응답을 남기고, 제공 결과를 바로 확정 정책으로 사용하지 않는다.
4. **공식 자료로 보완한다.** 시행기관 본문·모집공고·정정공고·첨부를 찾아 기관·연도·회차를 비교한다.
5. **정책과 근거를 연결한다.** 표준 정책 ID와 원천 ID를 구분하고, 원문 파일·출처·대조 내용을 연결한다.
6. **조건과 예외를 분리한다.** 기본조건, OR 경로, 제외조건, 기준 시점과 미확인 여부를 보존한다.
7. **형식과 내용 검증을 나눈다.** 자동 검사는 필수값·ID·날짜·참조 연결을 확인하고, 조건 해석은 근거자료와 대조한다.
8. **파일 또는 DB로 제공한다.** 파일 전달이면 스키마 설명을 동봉하고, DB 적재 시에는 타입·NULL·연결 관계를 정한다.
9. **운영용 갱신 절차를 추가한다.** 갱신 주기, 실패 재시도, 변경 비교, 재검토 담당과 마지막 확인일 표시를 별도로 구현한다.

예시 폴더 구성:

```text
project/
  docs/collection-method.md
  scripts/collect-api.*
  scripts/collect-official.*
  scripts/normalize.*
  scripts/validate.*
  data/raw/YYYY-MM-DD/
  data/processed/policies.json
  data/processed/sources.json
  data/processed/eligibility-rules.json
  data/review/candidates.json
  data/review/unresolved.json
```

DB로 확장한다면 정책, 출처, 정책-출처 연결, 자격경로, 후보 검토이력을 분리하는 구성을 검토할 수 있다. 원천 후보 한 건과 표준 정책 한 행이 항상 일대일로 대응한다고 가정하지 않는 것이 중요하다.

## 10. 현재 자료의 한계

이번 작업은 기준일을 둔 수집과 후속 조사이며, 정기 자동 갱신 시스템은 아니다. 공식 사이트 전체 게시물을 같은 조건으로 전수 수집한 결과도 아니다.

표준행의 모집상태 기준일은 2026-10-02이며, 후속 확인일은 항목별로 다르다. 문서 작성일인 2026-11-11 현재 모집상태를 다시 검증한 자료가 아니다. 일부 첨부, 후속 정정공고, 개별 자격, 예산과 공실은 미확정이다. API 호출한도와 제공기관 갱신주기도 확인하지 못했다.

다른 프로젝트에서는 이 자료를 수집·정리 방식의 사례로 활용하고, 실제 서비스에 사용할 정책 내용은 해당 서비스의 기준일에 맞춰 재확인해야 한다.

## 11. 보고서에 사용할 수 있는 설명문

> 청년 주거·생활비 정책 데이터는 온통청년 Open API를 통한 후보 수집과 중앙부처·지방자치단체·공공기관의 공식 자료 조사를 병행하여 구축하였다. API 응답과 웹페이지·첨부파일을 원문으로 보관하고, 정책명뿐 아니라 시행기관·연도·모집 회차·지원대상을 대조하여 표준 데이터로 정리하였다. 지원대상 원문은 구조화된 자격조건과 함께 보존하고, 기본조건과 예외 경로, 신청기간과 운영기간, 확인된 제한과 미확인 정보를 구분하였다. 정책별 식별자를 통해 출처와 검토 기록을 연결했으며, 구조·원문 연결 검증 후 JSON·TSV·엑셀 등의 형식으로 제공하였다. 수집과 파일 생성에는 스크립트를 활용했으나 조건 해석과 사업 선별에는 수동 검토를 병행했으며, 자동추천 및 정기 갱신은 별도 구현 범위이다.
