# 주거 조건 입력과 정책 필터 연결

## 사용자 입력

각 항목에서 하나를 선택한다. 체크 모양을 사용하더라도 동작은 단일 선택으로 구현한다. 미선택은 허용하며 조건을 적용하지 않는다.

| 표시 이름 | 저장 키 | 선택지 |
| --- | --- | --- |
| 현재 주거 형태 | housing_type | 월세, 전세, 공공임대, 기숙사/생활관, 자가, 기타 |
| 가구 구성 | household_type | 1인 거주, 가족과 거주, 배우자와 거주, 공동거주, 기타 |
| 주택 소유 여부 | home_ownership | 무주택, 유주택, 잘 모르겠음 |
| 세대주 여부 | household_role | 세대주, 예비세대주, 세대원, 잘 모르겠음 |

‘기타’는 사용자 선택값이고, 정책 조건의 ‘제한없음’ 또는 ‘확인필요’와 다르다. ‘잘 모르겠음’은 해당 조건으로 정책을 제외하지 않고 추가 확인 대상으로 표시한다.

공공임대에 월세로 거주하거나 가족·배우자와 함께 사는 경우에는 선택지가 겹칠 수 있다. 단일 선택을 사용할 경우 공공임대는 계약 유형보다 우선하고, 배우자가 함께 거주하면 ‘배우자와 거주’를 선택하도록 설명한다. 복수 선택으로 변경할 경우 정책 매칭 규칙도 함께 조정한다.

## 정책 데이터

현재 housing_2026-10-02.csv는 44컬럼이며 네 항목의 전용 컬럼이 없다. 사용자 프로필 값을 정책 행에 그대로 저장하지 않는다. 정책에는 허용 대상과 실제 자격조건을 저장한다.

기존 44컬럼을 사용하는 수집·검증 작업과 호환되도록 data_id로 연결하는 별도 조건표를 우선 사용한다. 통합 CSV가 필요한 경우 담당자와 스키마를 맞춰 아래 컬럼을 추가한다.

| 추가 컬럼 | 의미 |
| --- | --- |
| 주거형태조건 | 신청 시점에 허용되는 현재 주거 형태 |
| 가구구성조건 | 신청 시점에 요구되는 가구 구성 |
| 주택소유조건 | 본인 또는 세대의 주택 소유 요건 |
| 세대주조건 | 세대주·예비세대주·세대원 자격 요건 |
| 주거조건_원문 | 네 조건의 근거 문구와 예외 |
| 주거조건_출처 | 근거 컬럼명 또는 공식 원문 URL |
| 주거조건_검토상태 | 확인완료 또는 확인필요 |

값이 여러 개면 세미콜론으로 구분한다. 제한이 없다고 확인된 조건은 ‘제한없음’, 근거가 부족한 조건은 ‘확인필요’로 구분한다. 원문에 언급이 없다는 이유만으로 ‘제한없음’을 넣지 않는다.

원문은 기타조건뿐 아니라 지원대상_원문, 거주조건_원문, 제외대상도 함께 확인한다. 사업명·세부분류·추가태그는 검토 후보를 찾는 용도로만 사용한다. ‘전세 지원’이라는 사업명만으로 현재 전세 거주 요건을 만들지 않는다.

## 매칭 규칙

- 확인된 조건의 명확한 불일치만 제외한다.
- 미선택, ‘잘 모르겠음’, 정책의 ‘확인필요’는 해당 조건으로 제외하지 않는다. 필요한 경우 추가 확인 표시를 붙인다.
- 본인 무주택과 세대원 전원 무주택은 구분한다. 본인의 ‘무주택’ 선택만으로 세대 전체 무주택 조건을 충족했다고 판단하지 않는다.
- 혼인 여부와 현재 배우자와 거주 여부, 독립거주와 1인 거주를 같은 조건으로 취급하지 않는다.
- 예비세대주 인정 시점, 전입 기한, 신청일·대출 실행일 등 기준 시점은 원문에 보존한다.
- 같은 정책에 여러 신청 경로가 있으면 경로별 조건을 유지한다. 서로 다른 경로의 조건을 모두 필수 조건으로 합치지 않는다.

## 적용 범위

이 문서는 입력 선택지와 데이터 연결 설계다. 현재 저장소에는 조건 입력 화면 코드가 없으므로 화면 구현은 포함하지 않는다. 기존 CSV 값의 재분류와 스키마 변경도 아직 적용하지 않았다.
