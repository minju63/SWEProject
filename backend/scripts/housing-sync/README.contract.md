# 주거·생활 적재 형식 통일 · 2026-11-19

기존 주거·생활 DB 형식에 맞춰 자동 적재와 검토 후 적재를 함께 수정했습니다. 공통 변환·검사는 `record-contract.cjs`를 사용합니다. 이번 작업에서는 기존 DB를 삭제하거나 재삽입하지 않았습니다.

| 항목 | 적재 규칙 |
| --- | --- |
| 자격 조건 | `schema_version=eligibility/2`, `required`, `exclusions`, `review_notices`로 저장. 예전 `all/any/exclude`는 생성하지 않음 |
| AND/OR | 조건의 묶음과 대상자를 보존. 현재 자동 판정에 사용할 수 없는 조건은 `RAW`로 저장 |
| 표시 문구 | 기존 공통 한글 조건명 사용. 내부 필드명·true/false는 표시 문구에 노출하지 않음. 원래 규칙은 `original_condition`과 `review_ir`로 보관 |
| 출처 | 공식 공고 URL, 확인일, 본문 발췌, 해시를 함께 보관. 원본 전체는 기존 `policy_source.raw_data`에 보관 |
| 검증 여부 | 자동 적재와 현재 검토 적재는 `eligibility_verified=false`. 형식 통일은 전체 자격 검증이 아님. 새 데이터의 프로필 비교 항목은 근거 검토 후 별도 추가 |
| 기간 | 단일 날짜 범위가 공식 본문에도 확인될 때 날짜 저장. 월 단위·개인별·매월·미확정 기간은 임의 날짜를 만들지 않고 설명 저장. 예산 소진 조건 유지, 냉방·난방 기간을 공통 날짜 하나로 합치지 않음 |
| 대표·신청 URL | 확인된 기관 도메인만 허용. 블로그·뉴스·첨부 다운로드·마이홈 본문 조각 URL 차단. 잘못된 신청 URL은 NULL로 남기고 원본은 수집 자료에 보관 |
| 신청절차 | 공식 본문과 일치하는 문자열 배열 |
| 준비물 | `[{key, name, required, confirmed}]`. 조건부 서류 문구와 안정적인 key 유지 |
| 기존 값 | 기존 설명·금액·기간·자격을 자동 덮어쓰지 않음. 기존 신청절차·준비물은 NULL일 때만 채움. 개인 준비 체크와 타 분야 데이터는 수정하지 않음 |

기존 하루 1회 실행 명령 `housing-sync.cmd daily`와 Windows 예약 `SWEProject-Housing-Daily`를 그대로 사용합니다. 파이프라인 버전은 3입니다. 코드가 바뀌었으므로 예약을 새로 만들 필요가 없습니다. PC가 켜져 있고 예약된 사용자가 로그인되어 있어야 합니다.

예전 형식으로 중단된 적재가 일부라도 진행 중이면 새 형식으로 덮어 재개하지 않고 점검을 요구합니다. 완료된 옛 실행과 쓰기 전 실패는 새 수집으로 진행합니다. 기존 정책 재삽입을 위한 일괄 초기화 기능은 없습니다.

읽기 전용 점검:

```powershell
housing-sync.cmd check-contract
```
