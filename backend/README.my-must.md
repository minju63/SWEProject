## 이번에 보완한 부분

- 실제 `/map` 경로는 DB 지도 구현인 `pages/map/MapPage.jsx`로 연다. 기존 임시 화면의 메모리 찜을 사용하지 않는다. 거주지역이 없으면 임의의 구나 현재 위치를 만들지 않는다. 지도 프로필 캐시는 계정별로 구분한다.
- 장소 찜은 `user_saved_places`의 기존 본인 API를 사용한다. 재조회 실패 안내, 중복 클릭 제한, 저장 실패 되돌리기를 제공한다.
- 프로필을 바꾸면 지도 지역 캐시를 갱신한다. 마이에서 저장하면 홈·캘린더·찜·정책 관련 조회 캐시도 갱신해 이전 화면의 값을 계속 보여주지 않는다.
- 계정 설정에서 `/settings/username`, `/settings/email`, `/settings/password`로 들어간다. 아이디·이메일 변경 기능(FR-MY-018/019, Should)도 함께 구현했다.

## 아이디·이메일 변경

현재 로그인 계정의 등록 이메일은 서버에서 결정한다. 요청 본문의 다른 user_id나 이메일로 인증 대상을 바꿀 수 없다. 기존 SMTP 설정으로 6자리 번호를 보내고 5분 유효시간, 60초 재발송 간격, 5회 오류 제한을 적용한다. 원문 인증번호와 인증 권한 토큰은 작업 파일에 저장하지 않고 HMAC 값만 남긴다. 요청 목적과 계정이 다른 인증은 사용할 수 없다.

아이디는 소문자로 바꾸고 8~15자 형식·현재 값·중복을 최종 확인한다. 이메일은 등록 이메일 인증 후 새 이메일도 인증해야 바뀐다. 준비 중인 새 값은 가입 처리와 같은 파일 작업 저장소에서 예약하여 중복 사용을 막는다. 실제 변경은 기존 Auth 사용자 번호를 대상으로 하므로 프로필·찜·신청 기록의 연결이 유지된다. 가입 완료 기록도 새 값으로 갱신하며, 아이디 로그인은 Auth의 현재 아이디를 확인해 이전 아이디의 로그인 경로가 남지 않게 한다.

저장 응답이 끊기면 성공을 가정하지 않는다. 서버는 진행 중인 변경을 보존하며, 같은 변경 화면에서 인증번호 받기를 누르면 저장 결과 확인으로 이어진다. 이미 승인한 고정된 변경 요청만 다시 확인하고 임의의 새 값으로 바꾸지 않는다. 기존 SMTP 환경변수를 그대로 사용하며 별도 메일 서비스나 SQL 설치는 필요 없다.

## 검증과 운영 범위

마이·계정 관련 서버 테스트는 모의 Auth/저장소로 소유자 분리, 입력 검사, 암호화, 알림 설정, 날짜 전환, 삭제 재시도, 기존 값 보존을 확인했다. 커밋 전 관련 서버 테스트 33개와 브라우저 테스트 21개(마이 7·회원가입 12·캘린더 2)가 통과했다. 프론트 빌드도 통과했다. 실제 서비스 DB의 지도 장소 107건·분류 5개는 읽기 전용 조회로 확인했다. 실제 계정의 아이디·이메일 변경 검증은 완료하지 않았다.

가입 후 초기 설정은 간단한 기존 화면을 유지한다. 선택 동의한 회원의 초기 설정 완료 기록이 없으면 가입 직후뿐 아니라 홈 진입·재로그인 때도 초기 설정으로 이동한다. 저장 또는 건너뛰기를 완료하면 다시 열지 않으며, 선택 동의하지 않은 계정은 홈으로 이동한다. 완료 기록 저장·확인에 실패하면 성공으로 처리하지 않는다.

기존 SMTP 서버의 연결·인증 확인(`verify`)은 통과했으며 발송한 메일은 0건이다. 최신 백엔드 재시작 후 health 정상, 인증 없는 아이디·이메일·비밀번호 변경 시작 API의 401 응답을 확인했다. 프로필 변경 후 정책 조건·설명·비교 캐시도 비워 새 조건으로 다시 조회한다.

전체 서버 테스트 결과는 159개 중 158개 통과다. 기존 `test/policy-compare.test.js` 1개는 미검증 자격 조건을 `CHECK`로 처리하는 현재 코드와 `ELIGIBLE`을 기대하는 테스트의 차이로 남아 있다. 이후 추가한 가입 기록 갱신·만료 후 재발송 테스트 2개도 통과했다. 전체 테스트 통과로 기록하지 않는다. 프론트 기존 `routes.jsx`와 `useWorkspaceState.js`에는 Fast Refresh/React 훅 관련 린트 오류가 남아 있으며, 새 계정 화면·지도 화면 및 이번 서버 변경 파일의 린트는 통과했다.

현재 계정 작업 저장소는 파일 모드이며 서버 한 프로세스에서 실행한다. 루트 `.local/account-state.json`과 `backend/.local/profile-encryption-key.json`을 영구 보존해야 한다. 여러 서버에서 동시에 처리하는 DB 작업 저장소로 전환하는 것은 별도 작업이다. 다른 Supabase 프로젝트에는 반영하지 않았다.

실제 사용자는 마이 → 설정 → 계정 설정에서 변경 화면을 열어 등록 이메일 인증과 새 이메일 수신을 확인하면 된다. 아이디·이메일은 실제로 바뀌므로 시험할 경우 본인이 관리하는 테스트 계정으로 진행한다.

새로운 맞춤·정책·행사·시설 알림의 자동 생성(FR-MY-012~015, Could), 동의 관리 전문 화면(FR-MY-021, Should)은 이 Must 작업의 완료 범위에 포함하지 않는다.
