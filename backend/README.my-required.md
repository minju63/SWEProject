## 저장 위치와 실행 조건

새 SQL 설치나 테이블 추가는 없다. 알림 설정은 기존 비공개 `user-workspaces/<user_id>.json`에 `notificationSettings`로 저장하며 직접 입력한 신청 기록을 보존한다. 읽음 상태는 기존 `notification.is_read`에 저장한다.

현재 인증 작업 기록은 파일 모드다. 서버는 **한 프로세스**로 실행하고 `backend/.local`을 영구 보존해야 한다. 여러 서버에서 공유하는 인증 작업 저장소는 이번 작업 범위가 아니다.

- 발표일 전환: 한국 시간 매일 00:01. `MY_RESULT_JOB_ENABLED=false`이면 중지한다. 신청/캘린더 조회 시에도 지연된 전환을 보완한다.
- 요청된 탈퇴 재시도: 5분마다. `WITHDRAWAL_JOB_ENABLED=false`이면 중지한다. 취소·방치된 가입 요청의 자동 삭제는 기존처럼 별도 설정이다.
- 기존 마감 알림 생성: `ALARM_JOB_ENABLED=true`로 지정한 서버 한 곳에서만 실행한다.

7일 이내 삭제를 운영에서 지키려면 서버와 저장소가 계속 사용 가능해야 한다. 자동 재시도가 계속 실패하는 건은 운영자가 확인해야 한다. 테스트로 실제 계정이나 정책을 삭제하지 않았다. 정책 검증 이력은 보존하며 탈퇴자의 nullable `verified_by` 연결만 해제한 후 Auth 계정을 삭제한다.

## 검증 범위와 남은 항목

`my-required`, `my-withdrawal`, `my-settings-routes` 서버 테스트와 `my-required.spec.js` 브라우저 테스트는 모의 Auth/저장소/API를 사용한다. 실제 이메일 발송·실제 계정 탈퇴·실제 비밀번호 변경을 검증했다는 뜻은 아니다.

후순위 알림 자동 생성(FR-MY-012~016), 아이디·이메일 변경(FR-MY-018/019), 동의 관리 전문 화면(FR-MY-021)은 이번에 구현하지 않았다. 해당 유형은 DB에 기록된 알림을 조회할 수 있다. NFR-022의 민감정보 추가 보호는 기존 접근 제어와 별도로 보안 검토가 필요하며, 전체 요구사항 완료로 판정하지 않는다.

검증 결과: 관련 서버 테스트 34개, 브라우저 테스트 20개 통과. 프론트 빌드 통과. 최신 백엔드 재시작 후 `/api/v1/health` 정상 및 인증 없는 설정 조회 401 확인.

필수 기능 작업 직후 전체 서버 회귀 테스트는 139개 중 137개 통과, 2개 실패했다. 이후 주거 적재 형식을 통일하면서 `scripts/housing-sync/program-url.test.cjs` 실패를 해결했고, 관련 적재 테스트 45개가 통과했다. `test/policy-compare.test.js`의 자격 판정 기대값 불일치는 별도 후속 항목이다. 전체 회귀 통과로 기록하지 않는다.
