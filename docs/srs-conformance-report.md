# SRS v0.7 구현 점검표 (2026-11-22)

**방법**: SRS의 기능 요구사항(FR 139개)·비기능 요구사항(NFR 66개)·유스케이스(UC 28개)를 한 줄씩 코드·DB 스키마와 대조했고, 화면은 앱을 실제로 띄워 목업 56장을 새로 찍으면서 열어 봤다. 응답 시간은 일부만 측정했다.
**표시**: ✔ 코드·화면에서 확인 · △ 일부만 됨 또는 코드로는 확인 못 함 · ✘ 안 됨.
**한계**: 메일 인증 완료, 알림 실제 발송, 탈퇴 후 7일 삭제처럼 시간이 걸리거나 외부 서비스가 필요한 동작은 코드가 있는 것까지만 확인했다. 팀원 담당(검색·지도·마이)은 화면 열림과 핵심 기능 코드까지만 봤다.

## 1. 결론

- **유스케이스 28개**: 모두 대응하는 화면·기능이 있다. 처음 점검에서 구멍이던 UC-COM-003(정책 수집 서버 예약)과 UC-MY-004(알림 종류별 생성)는 코드를 추가했다(아래 2절). 단, 둘 다 DB SQL 실행과 서버 환경변수(`NOTIFY_JOB_ENABLED`, `HOUSING_SYNC_JOB_ENABLED`)를 켜야 실제로 돈다.
- **FR 139개**: 약 132개 ✔, 7개 △. 사진 질문(FR-H-002)은 제공하지 않기로 해 SRS에서 뺐다.
- **NFR 66개**: 대부분 ✔ 또는 코드 확인. ✘는 운영 로그 저장·삭제(NFR-COM-005·027), △는 성능 수치·접근성 측정 등.

## 7. 목업

SRS 수정본의 6.2 목업 56장을 현재 화면으로 교체했다. 메일 발송이 필요한 화면(아이디 찾기 완료·미가입, 비밀번호 인증·새 비밀번호)은 서버 응답을 흉내 내 캡처했고, 알림 센터(17번)는 테스트 계정에 알림이 없어 빈 목록이다.
