# SRS v0.7 구현 점검표 (2026-11-22)

**방법**: SRS의 기능 요구사항(FR 139개)·비기능 요구사항(NFR 66개)·유스케이스(UC 28개)·유스케이스 다이어그램 4장을 코드·DB 스키마와 한 줄씩 대조했다. 화면은 앱을 실제로 띄워 목업 56장을 새로 찍으면서 열어 봤고, 360px 너비·터치 영역·글자 대비는 자동 점검 스크립트로 쟀다.
**표시**: ✔ 확인함 · △ 일부만 됨 또는 확인 못 함 · 제외 = 요청으로 이번 범위에서 뺌.

## 1. 결론

- **유스케이스 28개**: 모두 대응하는 화면·기능이 있다. 유스케이스 다이어그램(4장)의 이름·개수도 본문 목록과 같고, 어긋나던 번호·행위자는 다이어그램을 다시 그려 맞췄다.
- **FR 139개**: 사진 질문(FR-H-002)과 장소 벡터 검색은 제외했고, 나머지는 모두 구현됐다. 약관·동의 관리(FR-MY-021)와 정책 상세의 출처·확인일·대체 안내를 이번에 채웠다.
- **NFR 66개**: 운영 로그 저장·30일 삭제, 검색 품질 평가, 360px·터치 영역·글자 대비 점검을 이번에 채웠다. 남은 것은 응답 시간 95% 측정과 일부 항목(아래 2절)이다.
- **데이터 수집**: 정책(주거·취업·진로·장학·금융)과 문화·장소·행사 데이터는 서버가 매일 자동으로 수집한다.
- **자동 테스트**: 백엔드 테스트 129건 중 2건이 실패한다. 하나는 가짜 Supabase 주소로 네트워크를 부르는 검색 테스트, 하나는 이메일 변경 테스트로 모두 이번 변경과 무관한 환경 문제다.

## 4. 유스케이스 다이어그램 대조 (5.1)

다이어그램 4장(공통·홈·캘린더·AI 비서 / 검색·상세 / 지도 / 마이)의 유스케이스 28개는 본문 UC 목록과 이름·개수가 같다. 이번에 두 장을 다시 그렸다.

| 다이어그램 | 고친 내용 |
|---|---|
| 공통·홈·캘린더·AI 비서 | UC 번호를 본문과 같은 `UC-COM-001`~`007`로, UC-COM-001에 네이버 백과사전 검색 API와 LLM API(OpenAI)를 행위자로, UC-COM-003에 공공데이터 출처(온통청년·고용24·공공데이터포털)를 명시 |
| 마이 | UC-MY-004에 "새 소식 알림 배치 스케줄러" 행위자 추가 |

검색·상세, 지도 다이어그램은 본문과 같아 그대로 뒀다. 본문의 UC 헤더 행위자 표기(UC-COM-001, UC-MY-004)도 같이 고쳤다.

## 6. 목업

SRS 수정본의 6.2 목업 56장을 현재 화면으로 교체했다. 메일 발송이 필요한 화면(아이디 찾기 완료·미가입, 비밀번호 인증·새 비밀번호)은 서버 응답을 흉내 내 캡처했고, 알림 센터(17번)는 테스트 계정에 알림이 없어 빈 목록이다.
