# SRS 수정 필요 사항 (홈·AI 비서 구현 기준)

- 작성: 백민주 (홈·AI 비서), 브랜치 `feature/home`
- 기준: SRS 통합본 v0.6-1
- 용도: 구현하면서 SRS와 달라졌거나 SRS에 정의가 없어 정해야 했던 내용입니다. SRS를 고칠 때 이 표를 기준으로 반영합니다.
- 구분: **변경** = 의도적으로 SRS와 다르게 구현, **미구현** = 아직 안 함, **정의 필요** = SRS에 없어서 임시로 정함

## 1. 용어 설명 방식 변경 (사전 + 네이버 백과사전)

사전에 없는 용어는 LLM이 기억으로 설명하지 않고, **네이버 백과사전(NAVER API HUB 검색)에서 찾은 글만 근거로** 쉬운 말로 요약합니다. 백과사전에도 없으면 지어내지 않고 모름 처리합니다. 사전 답변과 백과사전 요약은 화면에서 구분합니다.

동작 순서: ① 팀 용어 사전에 있으면 사전 답변 → ② 없으면 LLM이 질문에서 용어만 뽑아 네이버 백과사전을 검색(질문 원문은 보내지 않음) → ③ 가져온 글만 근거로 LLM이 요약(실패하면 가져온 글 그대로) → ④ 못 찾으면 "확인된 정보가 없어요" + 공식 사이트 안내. 정책 종류를 묻는 질문("청년 월세 지원이 뭐야?")은 백과사전 대신 **우리 정책 데이터에서 관련 모집 중 혜택을 찾아** 지원 내용 요약과 근거 카드 최대 3개로 답하고(일반 사전·LLM 기억 미사용), 관련 정책이 없으면 모름 처리합니다.

| 항목 | 현재 SRS | 구현 | 제안하는 SRS 문구 |
|---|---|---|---|
| FR-A12 용어 설명 | 용어 사전 기준의 쉬운 설명과 출처, 그 조건이 걸린 내 맞춤 혜택 | 사전 항목은 그대로(출처·내 맞춤 혜택 카드 포함). 사전에 없으면 네이버 백과사전 글을 근거로 요약하고 출처(네이버 백과사전·원문 링크·조회일)와 "백과사전 설명을 요약했어요" 안내를 붙임. 이 경우 내 맞춤 혜택 카드는 붙이지 않음 | 사전에 있으면 사전 기준으로, 없으면 외부 백과사전 검색 결과를 근거로 요약하고 출처와 공식 확인 안내를 함께 표시한다 |
| FR-A12 (추가) | — | 설명 속 어려운 말을 사전의 관련 용어로 이어 주는 "○○이 뭐야?" 칩(최대 3개) | 용어 답변 아래에 관련 용어 질문 칩을 표시한다 |
| FR-A18 모름 처리 | 근거 데이터·용어 사전에 없으면 "확인된 정보가 없어요" | 사전·백과사전 어디에도 없거나 API 키가 없으면 "확인된 정보가 없어요" + 공식 사이트 안내. LLM 단독 설명 경로는 없앰 | 근거 데이터·용어 사전·외부 백과사전 검색 결과에 없으면 모름 처리한다 |
| AI-REQ-01 근거 기반 응답 | DB 정책 또는 용어 사전만 근거 | 용어는 사전 또는 네이버 백과사전 검색 결과만 근거. 근거 없는 LLM 설명은 허용하지 않음 | 외부 공식 백과사전 검색 결과를 근거에 포함한다 |
| AI-REQ-05 생성 결과 검증 | 인용 ID·정책명·날짜·금액이 DB와 일치 | 정책 안내 문장은 숫자·정책명이 원문과 같을 때만 사용. 백과사전 요약은 "글에 없는 내용 추가 금지" 지시로 제한하고 원문 링크를 함께 제공(자동 일치 검증은 없음) | 백과사전 요약은 원문 링크 제공 의무를 두고 자동 검증 대상에서 제외한다 |
| AI-REQ-10 용어 사전 | 팀이 작성한 30~50개, 사전 밖은 "확인된 정보가 없다" | 50개 초안 작성(`backend/src/data/glossary.js`). 사전 밖은 네이버 백과사전 검색 후 요약 | 사전 규모는 50개 이상으로, 평가는 "사전 안 질문 정확도"와 "사전 밖 질문의 출처 표시·모름 처리 적절성"으로 나눈다 |
| FR-A14 답변 출처 | 용어 답변에 사전 출처명·URL·갱신일 | 사전 답변은 출처 기관·URL(갱신일은 팀이 확인한 날짜가 있을 때만). 백과사전 답변은 "네이버 백과사전 · 조회일 · 원문 보기" | 갱신일을 "팀 확인일"로 정의하고, 외부 백과사전 답변은 "조회일"을 표시한다 |
| 2.3 외부 API 목록 | OpenAI 등 | **네이버 검색 API(백과사전) 추가.** NAVER API HUB 사용, 환경변수 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`. 호출 주소 `https://naverapihub.apigw.ntruss.com/search/v1/encyc` | 외부 API 목록과 호출 한도(화면 표시 기준 하루 25,000회·월 775,000회, 초과 시 정책은 미확인)를 적는다 |
| 호출량 관리 | — | 같은 용어는 서버 메모리에 24시간 저장해 다시 호출하지 않음. 응답 지연 시 3초에서 끊고 모름 처리 | 캐시 정책과 타임아웃을 비기능 요구에 적는다 |
| NFR-017·NFR-023 개인정보·고지 | 외부 AI 전송 시 마스킹, 국외 전송 고지 | 네이버로는 질문 원문이 아니라 추출한 **용어만** 보냄. OpenAI 국외 전송 고지는 그대로 | 외부 검색 API에는 용어만 보낸다고 명시 |

**팀 작업 필요**: 용어 50개의 설명·출처 URL·확인일은 초안입니다. 감수 후 `updated`(확인일)를 채우고, 각 항목의 `url`을 설명이 실제로 나오는 페이지 주소로 바꿔야 합니다. 네이버 API 키는 팀 공용 계정으로 발급하고, 한도 초과 시 과금 여부를 요금 안내에서 확인해야 합니다.

| 항목 | 내용 |

| NFR-005 로그 | `[ai] type= llm=used/fallback/rejected/off ms=` 형식으로 기록. 질문 원문·사용자 식별 정보는 남기지 않음 |

| NFR-023 국외 AI 고지 | AI 비서 첫 사용 시 안내와 [확인했어요] 버튼 (회원가입 동의 화면 고지는 로그인 담당) |

| FR-A10 거주 구 판정 | 질문(또는 마이)에 거주 구가 있으면, 정책 지역(policy_region)에 **다른 구만** 있는 정책은 "대상 아님"으로 제외(부산 전체·전국 정책은 유지). 예: 사하구 거주 → 부산진구 전용 정책 제외. 홈·검색의 공통 판정 규칙은 건드리지 않고 AI 비서 안에서만 적용 |
| FR-A11 질문 결과 + 비슷한 혜택 | 질문에 "월세·전세·이사비·교통비·면접·정장·자격증·학자금·장학금 …" 같은 주제어가 있으면 그 말이 들어간 정책(신청 가능·확인 필요)을 먼저 보여주고, 3건이 안 되면 **같은 분야에서 신청할 수 있는 비슷한 혜택**으로 채움(카드에 "비슷한 혜택" 표시). 질문에 맞는 정책이 없으면 "○○ 관련 모집 중 혜택은 지금 없어요" 안내 후 같은 분야 혜택 표시. 홈 [AI 맞춤 추천]은 기존대로 "추천 TOP 3"("오늘의" 표현 삭제). 주제어 목록은 임시 |
| FR-A13 조건 표시 | 카드의 조건을 항목별 결과로 표시: "나이 19~34세 충족", "부산 거주 충족", "현재 상태(대학생·휴학) 충족", "소득 기준 확인 필요" 등. 문장형 조건은 콜론 앞 제목만 표시, 같은 문구는 한 번만, 최대 5개(충족→불충족→확인 필요 순) |
| FR-A11·A13 이어서 묻기 | "전부 알려줘·모두 보여줘" 같은 후속 질문은 **직전 답변의 주제어·분야를 이어서** 질문과 맞는 정책을 모두 표시(최대 30건, 3건 제한 해제). 질문과 맞는 정책이 3건보다 많으면 "전부 보려면 '전부 보여줘'라고 물어보세요" 안내와 [전부 보여줘] 칩 표시. 이어갈 주제가 없으면 모름 처리 대신 "어떤 혜택을 전부 보여드릴까요?"라고 되물음. SRS FR-A13의 "근거 카드 최대 3개"에 "사용자가 전부를 요청하면 예외" 추가 필요 |
| FR-A17 동네 이름 | "서면에 도서관 어디있어?"처럼 동네 이름(서면·하단·다대포·괴정·감천 등)을 말하면 주소·장소명에 들어가는 동 이름으로 바꿔 그 동네 장소만 표시(서면 → 부전·전포 등). 동네 목록은 임시. 서비스 지역 밖 동네(해운대 등)는 "확인된 장소 정보가 없어요", 해당 동네에 장소가 없으면 "○○ 근처에서 확인된 장소 정보가 없어요". 장소 답변 문장은 LLM이 다듬지 않고 고정 문구 사용 |

## 3. 구현과 SRS가 다른 곳 / 아직 안 한 것

| 항목 | SRS | 현재 | 제안 |
|---|---|---|---|
| AI-REQ-04 조건 추출 | LLM이 조건 JSON 추출, 정확도 85% 목표 | **구현함.** LLM이 질문에서 의도·분야·만 나이·거주 구·현재 상태를 한 번의 호출로 JSON으로 뽑고, 허용된 값(구 목록, 정책에 쓰이는 현재 상태 값 등) 밖이거나 불확실하면 null로 버린다. 판정은 공통 규칙이 한다. 뽑은 조건은 그 질문의 판정에만 쓰고 저장하지 않으며, 답변에 "질문하신 조건 …으로 확인했어요"를 표시한다. LLM이 꺼져 있거나 실패하면 키워드 규칙으로 대신한다. 소득·가구·주거 형태 등 나머지 조건은 아직 뽑지 않는다 | 추출 대상 조건 목록을 SRS에 명시하고, 수작업 라벨 50건으로 정확도 평가(85%)를 실제로 수행 |
| AI-REQ-07·08 검색 | SQL/벡터 검색, 임베딩(text-embedding-3-small), Top 5 80% | 정책명 키워드 매칭. 벡터 검색·임베딩 없음 | 벡터 검색 도입 여부 결정. 안 하면 SRS 2.3 외부 API 목록과 AI-REQ-07·08 수정 |
| AI-REQ-09 추천 문장 | LLM이 선택된 3건과 근거만으로 안내문 생성 | 안내문은 고정 문구 템플릿이고, LLM은 이를 다듬기만 함 | 위 동작대로 문구 수정 |

## 6. AI 비서 동네 검색을 법정동 기준으로 변경 (FR-A17, 지도 탭 연동)

- 동네 이름(서면·다대포·부전 등) 질문은 주소 글자가 아니라 장소의 법정동(`v_map_places.legal_dong`)으로 판단한다. 지도 탭 `mapUtils.js` 와 같은 규칙이라 [전체 보기]로 연 지도 결과 수와 같다.
- 서면 → 부전동·전포동, 다대포 → 다대동, 그 밖의 동네는 `OO동`. 서비스 지역 법정동(부산진구·사하구 18개)만 동네로 인정한다.
- 법정동을 아직 모르는 장소(`legal_dong` 이 null)만 주소 글자로 찾는다. 도로명에 든 동 이름(가야대로·당감서로·다대로)에는 걸리지 않는다.
- 범일(동구)은 서비스 지역 밖으로 보고 '장소 안내는 사하구·부산진구만 지원해요'로 답한다.

## 7. 홈 '공간·시설' 분야에 공간 관련 정책 표시 (FR-H10·H11)

- 홈 분야 아이콘 '공간·시설'은 이제 지도 장소 수(도서관·체육시설 등)가 아니라, 그 분야에 등록된 정책(청년문화공간 운영, 인디스테이션 운영 등) 중 모집 중·상시인 것의 수를 센다.
- 분야를 누르면 다른 분야처럼 정책 카드 최대 3건을 보여 준다. 도서관·체육시설 같은 장소는 카드 아래 안내 문구의 '지도 탭' 링크로 안내한다.
- '전체 보기'는 공간·시설 정책이 검색 분야에서 빠져 있어 지도 탭(`/map`)으로 이동한다. 지도 장소 수는 홈 중앙 총 개수에도 더 이상 포함하지 않는다.

## 8. 알림 종·알림 센터 (FR-COM-17, FR-MY-008)

- 모든 탭 헤더의 종 아이콘은 공용 `NotificationBell` 하나를 쓴다. 마이 탭 모양의 종, 배경 동그라미 없이 종만 그린다.
- 로그인했을 때 읽지 않은 알림 수를 종 오른쪽 위에 파란 숫자로 보여 준다. 0건이면 숫자를 숨기고, **100건 이상은 `99+`**.
- 개수는 **30초마다** 다시 가져오고, 브라우저 탭·창으로 **돌아올 때 즉시** 다시 가져온다.
- 종을 누르면 알림 센터(`/notifications`)를 연다. 알림 센터는 실제 알림(`notification` 테이블)을 보여 준다: 최근 30일, 최신순, 읽음 처리, 모두 읽음, 알림의 링크로 이동.
- 알림 종류 필터: 서버 값 `DEADLINE`→**마감**, `NEW_MATCH`→**혜택**, `SYSTEM`→**안내**. 기존 화면의 "신청" 필터는 해당 서버 값이 없어 "안내"로 바꿨다. (SRS에 알림 종류 이름이 정해져 있으면 맞춰 주세요.)
- API(`/api/v1/me`): `GET /notifications`, `GET /notifications/unread-count`, `PATCH /notifications/:id/read`, `POST /notifications/read-all`. 모두 로그인 필요.
- 알림은 찜한 정책의 알림 시각이 되면 알림 작업(`ALARM_JOB_ENABLED=true`인 서버 한 곳)이 만든다. 웹 푸시는 아직 없다.

| 상태 점(FR-A06 부근) | AI 비서 시트 머리의 초록 점을 6px로 줄이고 "AI 혜택 비서 · …" 글씨와 세로 가운데 정렬 |
| 당일 마감 표시 | 마감일 당일은 "D-0" 대신 **"D-day"**로 표시(홈 마감 임박, 캘린더, 정책 카드 모두 같은 표기) |
| AI 비서 카드 찜 (FR-A15) | 누르는 즉시 버튼 색만 바뀌고 글자는 "찜" 그대로(이전: "찜함"으로 변경). 서버 저장은 뒤에서 하고 실패하면 되돌림. 다시 누르면 찜 해제. "찜했어요" 안내는 홈·AI 비서 모두 **1초** |
| 홈 카드 찜 하트 | 하트를 원 안 가운데에 정렬. 누르는 즉시 붉게 바꾸고(낙관적 갱신) 서버 결과로 다시 맞춤 |
| 캘린더 | 개발용 샘플(목업) 데이터와 `?preview=1` 미리보기 모드 삭제 |

## 10. 추천·AI 비서 답변 규칙 변경 (FR-H04, FR-A08, FR-A10, FR-COM-03)

- **홈 'AI 맞춤 추천'과 챗봇 추천은 같은 판단을 쓴다.** 거주 구가 정해져 있으면 다른 구만 대상인 정책(예: 사하구 거주자에게 부산진구 정책)은 "대상 아님"으로 보고 추천에서 뺀다. 부산 전체·전국 정책은 그대로 둔다. (이전에는 챗봇만 이 규칙을 썼다.)
- **추천 순서(FR-COM-03)**: ①관심분야 일치 → ②그 밖 → ③대상 아님 → ④마감, 같은 단계에서 신청 가능 > 확인 필요 순, **그다음 내 조건에 더 많이 맞는 정책 먼저**(충족으로 판정된 조건 수 + 내 구가 정책 지역에 명시되면 가산), 그다음 모집 상태·마감일·가나다.
- **정책명 인식**: 질문에 "취업에"·"월세"·"2026"처럼 흔한 분야 단어·조사 붙은 말·연도/숫자가 있다고 해서 특정 정책을 가리킨 것으로 보지 않는다. 정책 이름 자체(또는 이름에만 있는 단어 2개 이상)가 있을 때만 그 정책으로 답한다.
- **AI 비서 정책 카드**: 충족(✓)·불충족(✕)으로 판단된 조건만 보여 주고, "확인 필요"(?)뿐이면 그 줄 대신 **정책 설명**(최대 3줄)을 보여 준다. 카드의 "상세 보기"는 `/policies/:id`로 연결한다(이전에는 비활성).
- **조건 문구**: 판정 결과에 맞춰 "만 18~39세 **충족**" / "…**불충족**" / "…확인 필요"로 적는다(이전에는 충족된 조건에도 "확인 필요"가 붙었다). '그 밖의 조건' 같은 모호한 말 대신 공고의 조건 문장을 그대로(26자까지) 쓰고, 여러 조건 중 하나만 맞으면 되는 묶음은 맞은 쪽만 보여 준다(예: "부산 거주 충족").
- **홈 '전체 보기'**: 검색 탭이 받는 형식(`/search?category=<분야 이름>&mine=true`)으로 이동해 분야·내 조건 필터가 적용된 채 열린다.

## 11. 취업·진로 정책 데이터 기준 변경 (팀 공통 신청 자격 표준)

- `policy.eligibility_conditions`를 `required`(필수 조건)·`exclusions`(제외 조건) 형식으로 바꿨다. 공고 원문과 DB 값을 직접 대조해 확인한 정책만 `eligibility_verified = true`, 아니면 false(화면에는 "확인 필요"). 근거(`source_url`, `checked_at`, `verified_by`, `verification_notes`)를 함께 저장한다.
- 개인이 신청하지 못하는 기업·기관 대상 정책 25건은 삭제했다(DB 직접 실행).
- 부산일자리정보망 프로그램 30건을 **'부산일자리정보망 청년부산잡스'** 1건으로, 2건을 **'부산일자리정보망 JOB프로그램'** 1건으로 합쳤다(상시, 신청 자격 없음, 프로그램별 대상은 각 공고에서 확인).
- 변환·반영 스크립트: `backend/scripts/eligibility/`. 반영 전 백업을 만들고 `--restore`로 되돌릴 수 있다.
