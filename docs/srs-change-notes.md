# SRS 수정 필요 사항 (홈·AI 비서 구현 기준)

- 작성: 백민주 (홈·AI 비서), 브랜치 `feature/home`
- 기준: SRS 통합본 v0.6-1
- 용도: 구현하면서 SRS와 달라졌거나 SRS에 정의가 없어 정해야 했던 내용입니다. SRS를 고칠 때 이 표를 기준으로 반영합니다.
- 구분: **변경** = 의도적으로 SRS와 다르게 구현, **미구현** = 아직 안 함, **정의 필요** = SRS에 없어서 임시로 정함

## 1. 용어 설명 방식 변경 (B안)

사전에 없는 용어도 답하도록 바꿨습니다. 사전 답변과 AI 설명을 화면에서 구분합니다.

| 항목 | 현재 SRS | 구현 | 제안하는 SRS 문구 |
|---|---|---|---|
| FR-A12 용어 설명 | 용어 사전 기준의 쉬운 설명과 출처, 그 조건이 걸린 내 맞춤 혜택 | 사전 항목은 그대로. 사전에 없으면 LLM이 쉬운 말로 설명하고 "AI 설명" 표시와 주의 문구를 붙임 | 사전에 있으면 사전 기준으로, 없으면 LLM이 설명하되 AI 설명임과 공식 확인 안내를 함께 표시한다 |
| FR-A12 (추가) | — | 설명 속 어려운 말을 사전의 관련 용어로 이어 주는 "○○이 뭐야?" 칩(최대 3개) | 용어 답변 아래에 관련 용어 질문 칩을 표시한다 |
| FR-A18 모름 처리 | 근거 데이터·용어 사전에 없으면 "확인된 정보가 없어요" | 정책·장소는 그대로. 용어는 LLM이 확실히 답할 수 있을 때만 설명하고, 모르거나 LLM이 꺼져 있으면 "확인된 정보가 없어요" + 공식 사이트 안내 | 용어 질문은 AI 설명 예외를 명시한다 |
| AI-REQ-01 근거 기반 응답 | DB 정책 또는 용어 사전만 근거 | 용어에 한해 사전 밖 AI 설명 허용 (근거·출처 없음) | 용어 설명의 예외와 평가 방법(인용 일치율 제외 대상)을 적는다 |
| AI-REQ-05 생성 결과 검증 | 인용 ID·정책명·날짜·금액이 DB와 일치 | 정책 안내 문장은 숫자·정책명이 원문과 같을 때만 사용. AI 용어 설명은 검증 불가 | AI 용어 설명은 검증 대상에서 제외하고 대신 표시 의무를 둔다 |
| AI-REQ-10 용어 사전 | 팀이 작성한 30~50개, 사전 밖은 "확인된 정보가 없다" | 50개 초안 작성(`backend/src/data/glossary.js`), 사전 밖은 LLM 보충 | 사전 규모는 50개 이상으로, 평가는 "사전 안 질문 정확도"와 "사전 밖 질문의 표시·안내 적절성"으로 나눈다 |
| FR-A14 답변 출처 | 용어 답변에 사전 출처명·URL·갱신일 | 출처 기관·URL 표시. 갱신일은 팀이 확인한 날짜가 있을 때만 표시 | 갱신일을 "팀 확인일"로 정의 |

**팀 작업 필요**: 용어 50개의 설명·출처 URL·확인일은 초안입니다. 감수 후 `updated`(확인일)를 채우고, 각 항목의 `url`을 설명이 실제로 나오는 페이지 주소로 바꿔야 합니다.

## 3. 구현과 SRS가 다른 곳 / 아직 안 한 것

| 항목 | SRS | 현재 | 제안 |
|---|---|---|---|
| AI-REQ-04 조건 추출 | LLM이 조건 JSON 추출, 정확도 85% 목표 | **구현함.** LLM이 질문에서 의도·분야·만 나이·거주 구·현재 상태를 한 번의 호출로 JSON으로 뽑고, 허용된 값(구 목록, 정책에 쓰이는 현재 상태 값 등) 밖이거나 불확실하면 null로 버린다. 판정은 공통 규칙이 한다. 뽑은 조건은 그 질문의 판정에만 쓰고 저장하지 않으며, 답변에 "질문하신 조건 …으로 확인했어요"를 표시한다. LLM이 꺼져 있거나 실패하면 키워드 규칙으로 대신한다. 소득·가구·주거 형태 등 나머지 조건은 아직 뽑지 않는다 | 추출 대상 조건 목록을 SRS에 명시하고, 수작업 라벨 50건으로 정확도 평가(85%)를 실제로 수행 |
| AI-REQ-07·08 검색 | SQL/벡터 검색, 임베딩(text-embedding-3-small), Top 5 80% | 정책명 키워드 매칭. 벡터 검색·임베딩 없음 | 벡터 검색 도입 여부 결정. 안 하면 SRS 2.3 외부 API 목록과 AI-REQ-07·08 수정 |
| AI-REQ-09 추천 문장 | LLM이 선택된 3건과 근거만으로 안내문 생성 | 안내문은 고정 문구 템플릿이고, LLM은 이를 다듬기만 함 | 위 동작대로 문구 수정 |
| AI-REQ-03 프롬프트 주입 | 지시문으로 규칙 변경 금지 | 시스템 지시에 방어 문구, 질문 300자 제한. 검사 시나리오 미작성 | 평가 질문 세트에 주입 사례 추가 |
| FR-A15 대화 중 찜 | 찜 + 기본 알림 등록 + 토스트 | 찜만 함. 기본 알림은 알림 기능 미구현으로 보류. 토스트: "찜했어요! 캘린더에 마감일이 추가됐어요" | 알림 구현 후 연동, 목업 문구("캘린더와 기본 알림에…")와 통일 |
| FR-A19 대화 기록 | 최근 대화 이어서 하기 (Could) | 열어 둔 동안만 유지(메모리). 서버·기기 저장 안 함 | 저장하게 되면 NFR-016 30일 보관·탈퇴 시 삭제 적용 |
| NFR-027 로그 30일 보관 | 운영 로그 30일 후 자동 삭제 | 콘솔 로그만 출력 | 로그 저장소 정해지면 구현 |
| FR-H12·FR-A15 찜 | — | 비로그인이면 "로그인하면 찜할 수 있어요" 안내 | 비로그인 동작 정의 (아래 4절) |

## 4. SRS에 정의가 없어 임시로 정한 것

| 항목 | 임시 결정 | 확정 필요 |
|---|---|---|
| 비로그인 상태의 홈 | 맞춤정보 없음으로 보고 "맞춤정보를 설정하면…" + [설정하기]. 전체 목록은 볼 수 있음 | 로그인 구현 후 비로그인 홈 동작 확정 |
| FR-H04 그래프 총합 | 5개 분야 합. 공간·시설은 지도 탭 장소 수(내 맞춤/전체 같은 값)로 세어 합에 포함 | 공간·시설 개수의 정의(전체 장소 수 / 거주 구 장소 수) |
| FR-H07 분야 이름 | SRS는 "문화·예술", DB·화면은 "문화" | **결정: "문화"로 통일.** SRS의 "문화·예술"을 "문화"로 수정 |
| FR-H03 마감일시 | **결정: 마감일만 있으면 그날 23:59로 표시** (예: 12.12 → 12.12 23:59). DB는 변경 없음. 모집 상태 계산도 마감일 당일까지 "모집 중" | SRS에 "마감 시각이 따로 없으면 마감일 23:59" 규칙 추가. 정책별 실제 시각이 필요해지면 시각 컬럼 추가 |
| FR-H03 서류 진행률 | `required_documents` 개수 중 `user_document_check`에서 체크된 개수 | 선택 서류를 분모에서 뺄지 |
| FR-H11 전체 보기 | `/search?categoryId={분야 id}&mine=1` 로 이동. 검색 탭이 아직 이 쿼리를 읽지 않음 | 검색 담당과 쿼리 이름·값 합의 (공간·시설은 `/map`) |
| FR-H13 검색창 확장 | 구현하지 않음. 검색창만 표시, Enter 시 `/search?q=` 이동(FR-H02) | 검색 담당과 합의 후 구현 |
| FR-H02 사진 질문 | 사진 분석 기능 전이라 버튼 없음 | 기능 구현 시 추가 |
| FR-A02 말풍선 문구 | "마감 임박 혜택이 N개 있어요! 물어볼래요?" → 없으면 "나에게 맞는 혜택이 N개 있어요! 물어볼래요?". 둘 다 없으면 표시 안 함 | 상황 문구 종류와 우선순위 목록 |
| FR-A09 "내 정보 반영 중" | 생년월일·거주지·현재 상태 중 하나라도 있으면 "반영 중" | 판단 기준 확정 |
| 관심분야 저장 값 | `user_profile.interest_categories`에 분야 이름 또는 분야 id 둘 다 인식 | 저장 형식 하나로 정하기 (마이 담당) |
| 홈 분야 목록 정렬 안내 | 목업 문구 "정렬 ① 신청 가능 › ② 마감 임박 › ③ 가나다"를 그대로 표시. 실제 정렬은 FR-COM-03 | 실제 규칙과 안내 문구 일치시키기 |
| FR-A17 장소 질문 | "내 근처"는 서버가 후보 최대 60곳(이름·주소·좌표)을 내려주고 거리 계산·정렬은 브라우저에서만 함. 위치는 서버로 보내지 않음. 좌표는 화면에 표시하지 않음 | 후보 개수 상한 |
| Dr.부 캐릭터 | 임시 SVG 일러스트 | 디자인 이미지 확정 후 교체 (`SharkAvatar.jsx`) |
